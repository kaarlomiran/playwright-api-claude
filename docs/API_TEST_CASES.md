# DummyJSON API Test Suite - Test Case Specification

**Target:** https://dummyjson.com  |  **Total cases:** 114  |  **Stack:** Playwright API testing (`APIRequestContext`) + TypeScript

> This file is written to be pasted/attached into another Claude session as the input spec.
> The machine-readable twin is `test-cases.json` (same IDs). Generate one Playwright `test()` per row.

## How Claude should consume this file
1. One row = one `test()`; title format: `[TC-001] <Description>`. Tag with the Category column using `{ tag: ['@happy'] }`.
2. Group with `test.describe('<Module>')`. Files: `tests/api/<module>.spec.ts`.
3. `{{BASE_URL}}` = `process.env.BASE_URL ?? 'https://dummyjson.com'`. `{{ACCESS_TOKEN}}` / `{{REFRESH_TOKEN}}` come from a `beforeAll` login (`emilys` / `emilyspass`) in a fixture.
4. Send **no cookies** on negative auth tests (use a fresh `request.newContext()`), otherwise the site cookie can mask a 401.
5. Every assertion in the last column must become an `expect(...)`. Use `expect.soft` for body-shape checks, hard `expect` for status codes.
6. Write endpoints (POST/PUT/PATCH/DELETE) are **simulated** by DummyJSON: they return the expected payload but do not persist. Never assert on persistence (except TC noted as idempotency).
7. Tests tagged `@slow` / `@flaky-watch` are retried and tracked by the flaky-monitor skill.

## Notes / known behaviours (verified live on 2026-11-20)
- Valid login: `emilys` / `emilyspass`. Wrong creds -> 400 `Invalid credentials`; missing fields -> 400 `Username and password required`.
- No token -> 401 `Access Token is required`; bad/expired token -> 401 `Invalid/Expired Token!`; bad refresh token -> 403 `Invalid refresh token`; missing refresh token -> 401 `Refresh token required`.
- Browsers carry a session cookie from dummyjson.com, so a *browser* call to `/auth/me` without a header can return 200. Playwright `APIRequestContext` with a fresh context has no cookie and gets the 401.
- `limit`/`skip` invalid -> 400 `Invalid 'limit' - should be a positive number`. Non-existent ids -> 404 `<Resource> with id 'X' not found` (users with non-numeric id -> 400).
- Unknown category returns 200 with an empty list; unknown route returns an HTML 404 page.
- Exact totals (194 products, 208 users) can change; assert relationships (`total >= length`) rather than fixed counts.
